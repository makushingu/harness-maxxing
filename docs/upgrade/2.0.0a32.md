# Upgrade notes 2.0.0a32

Summary: costs are counted right, long sessions compact themselves, the root CLAUDE.md gets a short "Saving tokens"
section, and the service can be sandboxed with systemd (asks first).

## 1. Section "Saving tokens" in the root CLAUDE.md
- Check: `CLAUDE.md` (workspace root) already has a heading `## Saving tokens`, or the user removed it on purpose
  (noted in `projects/system/topics/update/memory.md`): nothing to do.
- Do: copy the section `## Saving tokens` (heading and its bullets) from `<CODE>/templates/workspace/CLAUDE.md`
  into the root `CLAUDE.md`, just before `## Harness Maxxing` (at the end of the file if that heading is gone).
  Change nothing else.

## 2. Sandbox the service (systemd hardening)
- Check: `maxxing doctor` shows "service sandboxing applied", or
  `/etc/systemd/system/claude-maxxing.service.d/10-hardening.conf` exists. If so, skip this step.
  If the service is not installed (`maxxing doctor` says so), skip it too.
- Ask first: it restarts the `claude-maxxing` service (the UI reconnects after a few seconds; running
  turns are not interrupted). Explain: the service gets systemd protections that do not limit what
  Claude sessions can do (they run in their own units) - no new privileges, read-only kernel settings,
  no kernel modules, read-only cgroups, no set-uid files, at most 2048 processes.
- Do: on yes, run `maxxing harden`. It restarts the service and undoes the change by itself if the service
  does not come back (exit 1: report the journal lines it points to). Undo later: `maxxing harden --undo`.

## 3. Webhook sources without a signing secret
- Check: the sources are `feed.hooks` in `/var/lib/claude-maxxing/config.json` (`{id, name, kind}`); their
  secrets are `feed_hooks.<id>.secret` in `/var/lib/claude-maxxing/secrets.json`. Look for a `stripe`, `shopify`
  or `github` hook whose secret is missing or empty - test emptiness only, never print a secret value. If none,
  skip this step.
- Do: tell the user those sources now refuse every event until the signing secret is set (source menu ->
  Set the signing secret; the dialog says where the service shows it). Do not delete or change the sources.

## 4. Telegram linked without its owner
- Check: `maxxing doctor` - the Telegram line says "linked without its owner". If not, skip this step.
- Do: tell the user the bot now answers nobody in that state; they link it again from Settings -> Telegram
  -> Link (one-time code, opened from their own Telegram account).

## 5. Tell the user, in a few lines
- The **cost shown on each session was overcounted** (Claude reports a running total that was added on every turn):
  they are recomputed from the logs at the first start - each session now shows its real cost.
- **Automatic compaction**: a session whose context passes 400k tokens is summarized and continues in a fresh
  thread (a note says so); Settings -> Claude changes the threshold or turns it off.
- Sign out now really signs that browser out: the server refuses its cookie afterwards, even a copy of it.
  Other browsers stay signed in; changing the password signs every browser out.
- Uploads are limited to 2 GB each and refused when they would leave less than 1 GB free on the disk
  (`upload_max_mb` / `upload_min_free_mb` in config.json).
- Links opened from an HTML page shown in Files keep that page's sandbox.
- Optional: `"update_verify_signature": true` in config.json makes `maxxing update` refuse a version whose commit
  or tag is not signed by a trusted key (see the command line reference). Mention it; do not turn it on.
