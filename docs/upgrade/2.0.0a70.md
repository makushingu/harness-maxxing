# Upgrade notes - 2.0.0a70 (instructions for Claude)

IMPORTANT security release. `maxxing update` already did the work: it ran `maxxing init` (managed crontab lines with
`MAXXING_CRON_DETACH=1`, `maxxing-jobs.slice`, skills rendered with the real paths, a memory cap drop-in for the web service, the
two new weekly jobs "Clean caches and old versions" and "Check dependencies for vulnerabilities" - created **turned
off** on an existing installation -, `"cron_keep_background": true` and `"unit_hardening": false` in config.json so
scheduled jobs and sessions behave as before - offer to turn them on, see the Crons page doc). The next updates move uv (only if it is ours) and the server's Python (only if it is older
than 3.11) and update the other components in the background; nothing of yours is replaced or shadowed. Do this, then tell the user in two or three
sentences what changed for them:

1. Check the components: `maxxing deps list` then `maxxing deps verify` (if a background update ran, wait for it:
   log `<state>/logs/deps-update.log`). If something is missing or
   "outdated", run `maxxing deps update` (as root) and look at its output. A "not owned by root" failure means files
   another user could replace (older installs extracted Node.js as uid 1000): `maxxing deps update node` re-installs
   it cleanly, otherwise `chown -R root:root` on the listed paths.
2. Free the space of the old layout: `maxxing deps clean --dry-run`, then `maxxing deps clean` (the second browser
   older installs downloaded for Remotion, old Node.js and Scrapling folders). Root's uv/npm/pip caches are shared
   with the other tools of the server: `--caches` only if the user agrees. Ask the user whether to turn on the two
   new weekly jobs (Crons page).
3. `maxxing doctor`: under 4 GB of RAM without swap it warns - offer to add a 2 GB swap file (ask first; re-running
   the installer does it: `bash <code dir>/install.sh`, it keeps everything else).
4. Tell the user about the behavior changes, only those that apply to them:
   - HTML previews no longer load `.json`, `.csv`, `.md`, `.txt`, `.pdf`... files next to the page: if a topic has a
     page that does, inline the data or move it to a `.js` file. Open preview links must be reopened once.
   - Nothing changes for scheduled jobs' background programs on this installation (`cron_keep_background`); a job
     that starts a server or a bot is still better as a systemd service (offer it if you see one).
   - Scripts or extensions posting more than 1 MB of JSON to a core route get "too large" (extension routes allow
     5 MB).
   - The first sign-in link (`maxxing setup-link`) is valid one hour.
5. The web service gets a memory cap at its next restart (60 % of the RAM, drop-in
   `claude-maxxing.service.d/20-memory.conf`); nothing to do. Re-running the installer replaces it by a cap written in
   the unit itself.

Existing "Memory compaction" and "Check for updates" jobs are left as they are. Nothing else to do.
