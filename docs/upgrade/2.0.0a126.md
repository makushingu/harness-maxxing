# Upgrade notes - 2.0.0a126 (instructions for Claude)

Summary: this version brings to `stable` everything that was tested on `beta` since 2.0.0a112: **Agents** (with
approvals, actionable notifications, agent groups, files), **E-mail** (mailboxes, mail for agents, Infra -> E-mail),
**Telegram modes**, **secret files** in Keys and the new **Infra** page. Agents and E-mail are off by default:
nothing changes for the user until they switch them on. Do not switch anything on yourself.

An install coming from 2.0.0a123 or 2.0.0a124 never got the notes of 2.0.0a113 to 2.0.0a122 (their numbers are lower):
the steps below gather them. Every step checks first, so an install that already applied them has nothing to do.
Keep every row and line the user wrote. If a file or a topic was deleted on purpose, do not re-create it; say so in
the report.

1. **Global `CLAUDE.md`** (`<workspace>/CLAUDE.md`):
   - command table: if no row mentions `maxxing agents`, add after the `maxxing mcp` row (or at the end of the table):

     ````
     | `maxxing agents list\|run\|send\|on\|off` | agents (Settings -> Features -> Agents): start one, hand work from one agent to another (`send`), switch on / off |
     ````

   - skills table: if no row mentions `maxxing-agents`, add after the `maxxing-mcp` row (or at the end); if no row
     mentions `maxxing-mail`, add after the `maxxing-infra` row (or at the end). Take both rows from the product
     template `templates/workspace/CLAUDE.md`.

2. **Help index** (`<workspace>/projects/system/topics/help/CLAUDE.md`), rows taken from the product template
   `templates/workspace/projects/system/topics/help/CLAUDE.md`:
   - add the rows `30-agents.md`, `31-agent-groups.md`, `32-mail.md` when missing (after the `29-team.md` row, or
     before the `CHANGELOG.md` row);
   - replace the rows `09-telegram.md`, `11-settings-and-keys.md`, `24-feed.md`, `27-infra.md`, `30-agents.md`,
     `32-mail.md` by the template's when they do not mention, in that order: the modes, secret files, alerts, the
     E-mail tab, groups or approvals, agents. A row the user rewrote stays.

3. **Telegram**, only if it is linked (`maxxing telegram status`) and the topic memory does not already say the modes
   were presented: run `maxxing telegram mode` and tell the user in two sentences that Telegram has modes now
   (Settings -> Telegram -> Mode) and which one this install uses:
   - `threads` or `mirror`: their threads were kept. A **Simple** mode exists (one chat: the alerts, and the sessions
     as replies - reply to a message to continue its session). Only if they want it: `maxxing telegram mode simple`
     (it deletes the session threads and the Crons / Alerts / Notifications threads in Telegram; the sessions stay in
     the web UI).
   - `simple`: the install chose it because the chat had no thread open at the update. If they used one thread per
     session before and want it back: `maxxing telegram mode threads`.

   Then note "Telegram modes presented" in the topic memory.

4. **Agents' sandbox**: new agents run in Claude Code's sandbox, which needs `bubblewrap`, `socat` and, on Ubuntu
   24.04+, an AppArmor profile; older servers may miss them. Only once the user uses agents (the agent's page or
   `maxxing doctor` then reports "agents' sandbox missing"), offer to run `maxxing agents sandbox-setup` as root;
   never install it unasked.

5. **Server problems in the notifications** stay off on this install (`health_feed`). If the user wants one place to
   follow everything (and the server problems on Telegram), tell them about Settings -> Notifications -> "Server
   problems in the notifications"; do not turn it on yourself.

Nothing else: the skills (`maxxing-agents`, `maxxing-mail`, `maxxing-feed`, `memory`, `memory-compaction`) were
refreshed by the update, and no data needs moving.
