# Upgrade notes - 2.0.0a67 (instructions for Claude)

Summary: path sites created with `maxxing infra site add --port` before this version still forward the Harness
cookies to their app. Everything else needs nothing: new settings (`short_titles_model` off,
`idle_compact_tokens` 200000, `claude_auto_update` off, `unit_memory_max` "75%") take their defaults, and new lock
files `<state>/.config.lock`, `<state>/.crons.lock`, `<state>/.claude-update.lock` (empty, mode 600) appear: keep them.

## 1. Strip the Harness cookies from existing path sites
- Check: list `/etc/caddy/maxxing-paths/*.caddy` (or `$MAXXING_CADDY_DIR/maxxing-paths`). Done when every file
  with a `reverse_proxy` line also has `header_up Cookie "mx_`, or when there is no such file.
- Do: for each site name `N` without it, `maxxing infra site remove N` then add it again with the same options
  (read them from the file: `--port`, `--project`, `handle` = `--keep-prefix`;
  skip a file with `header_up Host`: a public bucket, served by Garage on this server),
  then `maxxing infra refresh`. Folder sites (`root *`) only need the same remove / add to hide dotfiles.
  The app's own cookies and logins keep working.
- Ask first if: a site is in use right now (a few seconds of 404 while it is re-created) - say which.
